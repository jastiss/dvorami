# Экран прохождения: единый каркас и тема дела

Решение A-30 (вариант А), задача T-52, 23.11.2026. Каркас один для всех дел; дело меняет только оформление и артефакт.

## 1. Структура каркаса (одинаковая во всех делах)

| № | Блок | Что в нём | Где в коде |
|---|---|---|---|
| 1 | Шапка дела | логотип · «Дело № N · 5 из 12» · кнопка меню | `.pl-top` |
| 2 | Прогресс по точкам | полоса из сегментов, часть шапки: пройдено — толстый сегмент цвета дела, текущая — светлый, впереди — тонкая линия | `.pl-progress` |
| 3 | Заголовок экрана | строка «Точка 5 · дорога / на месте / пройдена», название точки, место | `.pl-head` |
| 4 | Карточка задания | тег шага текстом («Смотри», «Крути», «Думай», «По желанию»), «Шаг 2 из 4», текст; рамка — только у активного задания | `.pl-task` |
| 5 | Ввод ответа | поле 56 px и одна главная кнопка «Ответить» | `.pl-form` |
| 6 | Подсказки | одна кнопка-ступень «Подсказка 1 из 3 → 2 из 3 → Показать ответ», открытые подсказки остаются над ней | `.pl-hints` |
| 7 | Артефакт | улика (метка «буква + год» и слова свидетеля) и документ (строка `<code>` в тексте: телеграмма, шифр, пометка) | `.pl-art`, `.pl-doc` |
| 8 | Навигация | три постоянных раздела: **Точка · Улики · Карта**; на ширине от 1024 px — колонка слева, от 1280 px справа ещё «досье» с буквами | `.pl-nav`, `.pl-side` |

С 25.11 экран идёт по мини-шагам: один экран — одна реплика, загадка или разбор; над экраном строка «назад · где мы ▾» (название — вход в оглавление; отдельной иконки оглавления и второй полосы прогресса нет — владелец 27.11: «прогресс-бар под прогресс-баром… оглавление под бургер-меню»). Прогресс — **один индикатор**: полоса по точкам в шапке, текущий отрезок в рамке заполняется по ходу точки (дорога → шаги), поле ответа стоит в потоке под вопросом. Подробно — `quests/zilart/field/player-ui-v2.md`.
Главная кнопка экрана («Мы на месте», «Дальше», «Проверить», «К точке N») на телефоне всегда внизу над навигацией (`.pl-stick`); кнопки «К заданию» больше нет. Проверяет `player_check.js` на 390 (T-60).
Меню в шапке: заметка, светлая тема, «Сообщить об ошибке», пауза, «Начать заново» (в полевом тесте — отчёт). Повторное нажатие «Точка» возвращает к текущему заданию.
«Карта» — схема по настоящим координатам: только пройденные точки и текущая, маршрут вперёд не раскрывается.

Файлы: `site/play/player.css` (раскладка, значения по умолчанию — платформа «Синий час»), `site/play/player.js` (логика и вся разметка каркаса: шапку, навигацию и шторку строит скрипт, в странице дела их нет).

## 2. Тема дела — файл `site/play/<id>/theme.css`

Только значения переменных (тёмная тема в `:root`, светлая в `:root[data-theme="sun"]`) и вид артефакта.

| Группа | Переменные |
|---|---|
| Фон и поверхности | `--bg` `--surface` `--surface-2` `--line` `--page-bg` (сетка, зерно) |
| Текст | `--text` `--text-2` `--text-3` |
| Элементы | `--control` (рамки полей и вторых кнопок) |
| Акцент | `--accent` + `--on-accent-fill` (заливки), `--accent-text` (мелкий текст), `--accent-btn` + `--on-accent` (главная кнопка), `--ok` |
| Артефакт | `--paper` `--ink` `--ink-2` `--font-doc` |
| Шрифты | `--font-display` `--font-text`; заголовок: `--h1-size` `--h1-line` `--h1-weight` `--h1-case` `--h1-track`; кнопка: `--btn-font` `--btn-case` `--btn-track`; теги: `--tag-font` `--tag-track` |
| Форма | `--radius` `--radius-btn` `--btn-shadow` |

Сверх переменных теме можно: фигуру у заголовка (`.pl-deco`), вид артефакта (`.pl-art`, `.pl-art-mark`, `.pl-doc`, `.pl-letters span`, `.pl-card--paper`).
Нельзя: менять раскладку, размеры касаний, состав навигации и шапки, прятать блоки каркаса.
Требования к значениям: текст ≥ 4,5:1, рамки и кнопки ≥ 3:1 к своему фону, тёмная тема по умолчанию. Проверяет `scripts/player_check.js`.
«Авангард» (дело №1): главная кнопка на тёмном — `#E1251B` (к карточке 3,3:1; прежняя `#C81E17` давала 2,9:1); мелкий красный текст на светлом — только `#C81E17`, на тёмном — `#FF5A4E`.

## 3. Как подключить новое дело

1. `quests/<id>/quest.json` — как сейчас. На стенд дело попадает зашифрованным (`quest.locked.json`, собирает `pages.yml`), перед ним — экран кода доступа (`docs/codes.md`).
2. Скопировать `site/play/zilart/index.html` в `site/play/<id>/`: поменять `<title>`, `data-quest="<id>"`, `data-case-no="N"`, `data-case-url` (страница дела для «Нет кода?»), два `preload` шрифтов темы, `theme-color`.
3. Написать `site/play/<id>/theme.css` (образец — `site/play/zilart/theme.css`, 40 строк).
4. `node scripts/player_check.js --quest=<id>` — проходит дело от обложки до финала на 390/1024/1440 в обеих темах.

`player.css` и `player.js` при этом не трогаются. Проверено на макете: `platform/design/mockups/player-skin-demo/` — тема «Чертёж» (дело №4) подключена тремя файлами, каркас не менялся
(`node scripts/player_check.js --page=platform/design/mockups/player-skin-demo/ --data=platform/design/mockups/player-skin-demo/quest.json`).

## 4. «Живой» артефакт

Новая улика ложится на экран, метка ставится штампом; штамп «Верно» — так же; документ (телеграмма) печатается по букве; счётчик улик в навигации подпрыгивает; текущая точка на карте пульсирует.
Только `transform`/`opacity`, без библиотек, один раз при появлении экрана (класс `.pl-fresh`); при `prefers-reduced-motion: reduce` всё выключено.

## 5. Восемь проблем из разбора 23.11 (`player-review-2026-11-23.md`)

| № | Проблема | Итог |
|---|---|---|
| 1 | Три разных продукта вместо одного | Закрыто: один каркас, дело — файл темы; демо темы дела №4 на том же каркасе |
| 2 | Нижняя панель у каждого дела своя | Закрыто: «Точка · Улики · Карта» — разметка в `player.js`, тема её не меняет; тест сверяет состав |
| 3 | Панель как служебная строка | Закрыто: линейные значки одного набора, подписи 15 px без капса, высота 64 px, активный раздел отмечен полосой, жирностью и `aria-current` |
| 4 | Действия вперемешку с разделами | Закрыто: в панели только разделы; «Заметка», тема, ошибка, пауза — в меню; «Повторить» заменено повторным нажатием «Точка»; «Ещё» убрано |
| 5 | Шапка перегружена, прогресс трижды | Закрыто: «Дело № 1 · 5 из 12» и полоса — одно целое в шапке; кнопка темы ушла в меню; в заголовке точки «из 12» больше нет |
| 6 | Много рамок и капса | Закрыто: рамка только у активного задания, сцена и пройденные шаги без плашек; капс — только заголовок, теги и одна главная кнопка (и только в теме «Авангард») |
| 7 | Подсказки мелкие и тесные | Закрыто: одна кнопка 56 px, название 17 px, пояснение 15 px, без `opacity` |
| 8 | Светлые макеты №4 и №7 по умолчанию | Закрыто для плеера: тёмная тема по умолчанию у любого дела, светлая — переключатель в меню; на главной светлые макеты заменены экранами каркаса. Макеты `platform/site/mock-screens/case4.html`, `case7.html` устарели — не удалял |

Хвосты T-12: подписи подсказок ≥ 15 px; кнопки и подсказки без `opacity`; контраст 3:1 / 4,5:1 проверяется тестом на каждом экране; эмодзи шагов → текстовые теги (в том числе «По желанию» и «Версия Тюфеля», которые раньше оставались без тега).

Скриншоты: `platform/design/screens/2026-11-23/player-*-390.png` и `player-*-1440.png`.

## 6. Правила показа (владелец 25.11, после прохождения с телефона)

Подробно — `quests/zilart/field/player-ui-v2.md`. Обязательны для любого дела, проверяются `player_check.js`:
- один экран — одно новое (реплика, картинка, загадка, разбор); новый экран открывается сверху, «Дальше» и поле ответа в видимой зоне;
- клавиатура не двигает раскладку: поле в потоке под вопросом, навигация прячется на время ввода;
- любой пройденный мини-шаг открывается из оглавления и стрелки «назад»; непройденное не показывается;
- длинный текст сворачивается с треугольной стрелкой ▸/▾; анимации — только `transform`/`opacity` и только без `prefers-reduced-motion`.
