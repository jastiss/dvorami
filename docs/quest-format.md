# Формат дела: `quests/<id>/quest.json`

Плеер — `site/play/player.js`. Дело — данные: новый квест не требует программирования. Формат 3 (ЗИЛАРТ 3.1) работает как прежде; формат 5 добавляет поля, а не меняет старые, — любое поле можно не указывать.
Проверка: `node scripts/player_check.js` (дело из `quest.json`, зашифрованное, как на стенде) и `node scripts/player_check.js --data=scripts/fixtures/quest-format5.json --allow-missing-media` (все возможности формата 5 на трёх точках; с `--flags=t1:B` — ветка Б). Черновик дела — `--data=<файл>`.
Telegram-бот-ведущий (`scripts/quest_bot.py`) читает тот же `quest.json` и понимает те же поля и типы шагов (ветки, часы, временные объекты, развилка, `all`/`replies`, `choice`/`pick`/`strike`, вопросы на ходу); проверка ответа — `scripts/answer_match.check_text` = `checkText` в `answer.js` (сверка — `answer_check.js`). Тест без сети — `python3 scripts/test_quest_bot.py`: проходит оба дела и фикстуру «вслепую» правильными ответами, неверные не засчитываются. **Новый тип шага или поле ответа — в плеер и бот в одной правке, случаем в оба теста.**

## 1. Дело целиком

| `clock` | ветки «по часам работы»: `{"zum": {"label": "ТЦ «ЗУМ»", "open": "10:00", "close": "22:00"}}` (раздел 6а) | 5 |
| `speakers` | говорящие: `{"zilya": {"name": "Зиля", "style": "hero"}}` (раздел 3) | 5 |

| `cards` | карточки, которые лежат на доске с начала дела | 5 |

Ориентир: `{"kind": "water\|park\|river\|metro\|place", "label": "Пруд", "at": [lat, lon]` или `"point": N`, `"r"` — радиус в метрах (вода), `"area": [[lat, lon]…]` + `"pad"` (м) — контур парка, `"line": [[lat, lon]…]` + `"width"` (м) — река, `"from": N` — показывать с точки N (не подсказывать дорогу вперёд); **без `from`** — с первой точки, в тексте которой (дорога, сцена, шаги, итог) встречается `label` (без кавычек и регистра, ё = е); подпись не встречается нигде — виден сразу`}`. Координаты — только из точек дела и `research/` (не выдумывать). Нет поля — схема всё равно с севером, масштабом и путём | 5 |

## 3. Шаг

Общие поля любого шага:

| Поле | Что |
|---|---|
| `type` | `info` / `say` (прочитать → «Дальше»), `ask` (ответ словами), `free` (любой ответ), `choice` (вариант), `pick` (карточки доски), `strike` (вычеркнуть лишнее), `board` (формат 3) |
| `lines` | реплики перед заданием (ниже) |
| `text` | строка задания; эмодзи в начале → тег шага, как в формате 3 |
| `tag`, `tag_style` | тег явно: `"tag": "По желанию"` (стиль `opt`), `think`, `look`, `turn`, `cat` |
| `title` | подпись свёрнутых реплик в пройденном шаге (иначе — имена говорящих) |
| `button` | надпись главной кнопки `info`/`say` (по умолчанию «Дальше») |
| `audio` | озвучка шага |
| `hints` | подсказки; три — «намёк → почти решение → ответ», последняя у загадки — ответ. **У поля с вводом последняя подсказка должна засчитываться как ответ** — игрок может перепечатать её в поле (`player_check` краснеет, если нет). Исключение — `"any_answer": true` (засчитывается любой ответ) и `choice`, где верен любой вариант: такие поля проверка пропускает и печатает строкой «не проверяется — засчитывается любой вариант» |
| `src` | откуда берётся ответ (H-72): `place` — только на месте (надпись, вид, счёт шагов), `text` — из текста дела, доски или письма, `both` — нужны оба. `player_check` печатает долю полей «с места» по проходимой ветке и предупреждает, если меньше ⅔. Пока разметки нет — строка «разметки src нет»; красным станет, когда разметка пройдёт по всем делам |
| `ok` | после ответа: строка или список реплик |
| `ok_on_skip` | показать `ok` и после «Пропустить» |
| `optional` | можно пропустить |
| `cards`, `add`, `strike`, `unstrike` | карточки на доску (определения или id) и вычёркивания — после шага (при любом исходе) |
| `letter` | состояние письма — **с началом шага** (реплика `{"doc": "letter"}` в этом шаге уже показывает новое) |
| `if` | ветка (раздел 6) |

### Реплика (`lines`, `scene`, `walk`, `intro`, `ok`, `outro`, `finale`)

| Вид | Пример |
|---|---|
| реплика | `{"who": "zilya", "text": "Курлык!"}`; `note` — пометка после имени, `audio` — кнопка «Слушать» под репликой. Без `who` — абзац рассказчика без имени (говорящего по умолчанию нет) |
| строка | `"Просто абзац"` |
| «стрелка» | `{"arrow": "hint", "text": "Застряли — здесь три подсказки"}`: цели `sound` (кнопка звука), `image` (картинка), `board` (доска улик: вкладка мигает), `hint` (подсказки), `plus` (вопрос на ходу), `letter` (письмо). Встаёт **под своим элементом** на том же экране; нет элемента — там, где написана. Показывается **один раз** за прохождение |
| картинка | `{"img": "media/ch1.jpg", "alt": "…", "caption": "…", "ratio": "3 / 2"}`; `"img": null` — **заглушка** «Картинка готовится» с подписью; файл не загрузился — та же заглушка, раскладка не прыгает. С `text` (и `who`) — под картинкой реплика, как обычная: её озвучивает и отмечает плеер экрана; с `audio` без `text` — звуковая улика под картинкой (`transcript`, раздел 4) |
| слои | `{"layers": ["a.jpg", "b.jpg", "c.jpg"], "alt": "…"}` — касание меняет слой |
| письмо | `{"doc": "letter"}` — текущее состояние письма; `{"doc": "letter", "state": "s6"}` — заданное |
| карточка | `{"doc": "card", "id": "c-photo"}` — карточка доски целиком |
| строка «о свете» | `{"who": "titr", "sun": 180, "text": "Сегодня стемнеет около {время}…"}` — остаётся, только если до захода солнца меньше `sun` минут (или он уже был); `{время}` — заход по дате для координат первой точки, по Москве. Во вступлении такая строка повторяется и на обложке. Проверить: `?at=14:00` |

**Разметка текста** (реплики, шаги, карточки): `<b> <i> <u> <s> <code>` и ссылка `<a href="https://…">текст</a>` или относительная (`<a href="../../moscow/">`). Ссылка с другой схемой (`javascript:`, `http:`, `//…`) остаётся простым текстом; внешняя открывается в новой вкладке, у всех — `rel="noopener"`. Прочие теги показываются как текст.

Стили говорящих (`speakers.*.style`): `hero` (сплошная полоса цвета дела), `cat` (пунктир), `witness` (двойная), `radio` (точки, моноширинный), `titr` (курсив без имени — имя только для чтения с экрана), `note` / `card` (бумага), `letter` (бумага и рукописный курсив). Имя говорящего подписано всегда — различие не только цветом.

### Ответы

| Поле | Тип шага | Что |
|---|---|---|
| `answers` | `ask` | варианты, как в формате 3: слово или фраза совпадает с ответом целиком или словами подряд; `~` в начале — «содержит» (`~корзин`) |
| `all` | `ask` | ответ из частей: `[{"answers": [...], "missing": "Кому — верно. А какая вещь?"}, …]` — нужны все; совпала часть — `missing` той, что не совпала |
| `replies` | `ask`, `walk_ask` | «почти»: `[{"answers": ["~роща"], "text": "Тепло: это фамилия…"}]` — показывается вместо «не подходит». Порядок проверки: `answers` → `all` целиком → `replies` → `missing` → опечатка |
| (нормализация) | `ask`, `walk_ask` | движок прощает сам, в `answers` не нужно: регистр, ё/е, кавычки и знаки, дефисы, пробелы; числа цифрой и словом («3» = «три», «1 931» = «1931», год словами). **Падежи и синонимы движок не угадывает** — их перечисляет карточка загадки, и все они идут в `answers`. Одна опечатка в ответе от 5 букв (у `~`-основы — от 6) или верные слова вперемешку с лишними — «Почти! Проверьте написание», не засчитывается; годы и числа опечаткой не считаются. Код — `site/play/answer.js`, тест каждой загадки — `scripts/answer_check.js` (входит в `player_check`) |
| `placeholder` | `ask`, `free` | подсказка в поле |
| `options`, `answer`, `answer_flag` | `choice` | `[{"id": "А", "label": "…", "img": null, "reply": "…"}]`; `answer` — id верного; `answer_flag: "st7"` — верный вариант берётся из флага, если флаг равен id варианта (портрет «по натуре») |
| `shuffle` | `choice` | **варианты перемешиваются** (H-73): порядок у каждого игрока свой и постоянный (seed в сохранении + дело + точка + шаг), на кнопках — буквы А, Б, В по месту на экране; внутренний `id` игрок не видит. Порядок данных остаётся, если: `"shuffle": false`; варианты нумерованные — `id` из одного знака (`А`–`Г`, `1`–`3`: на них ссылаются рисунки и подписи; знак показывается, если подпись с него не начинается); засчитывается любой вариант (порядок там смысловой). У нумерованных автор сам ставит верный не первым. `player_check` предупреждает, если верный вариант заметно длиннее остальных (угадывается по длине) или у всех неверных одно первое слово, а у верного — другое («Главная аллея» против трёх «Проезд …») |
| `pick`, `answers`, `near` | `pick` | выбрать `pick` (по умолчанию 2) карточек доски: `answers: [["c-pond", "c-seva"]]` (порядок не важен), `near: [{"set": [...], "text": "Тепло…"}]` |
| `items`, `img` | `strike` | `[{"id": "trees", "label": "Деревья", "keep": true, "reply": "Эти — ушли?"}]`: вычеркнуть все без `keep`, не тронуть с `keep`; `reply` — ответ на ошибку с этим пунктом |

## 4. Звук

`audio` у точки, шага, вопроса на ходу, реплики: путь к файлу (`"media/audio/ch1.mp3"`) — кнопка «Слушать / Пауза»; `true` — **место под озвучку**: кнопка «Озвучка скоро» (не играет, говорит, что звука пока нет). Нет файла по пути — тост «Озвучка ещё не готова», квест идёт дальше.

**Субтитры (H-62): звук без текста на экране не играет.** Озвучена может быть только реплика с `text` — её текст всегда на экране; пока она звучит, плеер отмечает её, а свёрнутый хвост («Подробнее») раскрывает, когда голос до него дошёл. Звуковая улика без реплики — `{"audio": "media/audio/tram.mp3", "transcript": "Трижды звякнул трамвай"}`: `transcript` (или `caption`) показывается под плеером, и при `audio: true` тоже. Без `transcript` — `player_check` красный: в данных и в `?field=1` на каждом экране (плеер улики помечен `data-clue` и засчитывается только своим текстом сразу под ним, а не репликой рядом — T-134).

## 5. Доска улик и письмо

**Карточка** — `{"id": "c-pond", "title": "Пруд", "text": "…", "kind": "photo", "img": null, "alt": "…", "source": "…", "struck_label": "Вычеркнуто"}`. Определяется один раз — в `cards` любой точки, шага, вопроса на ходу или дела; в других местах на неё ссылаются по id. Источник («Остановка N») подставляется сам. `kind: "photo"` или `img` — кнопка «Открыть» (шторка с картинкой). Вычеркнутая — зачёркнута и со штампом «Вычеркнуто». Карточки с `"kind": "version"` — версии: живые — над письмом, опровергнутые (вычеркнутые) — одной строкой со штампом «Отпала» внизу доски (T-118: короткий штамп не обрезает заголовок на 390), полный текст и причина — по нажатию. От 8 карточек (с письмом) — переключатель «Все · Версии · Улики».
Доска формата 5 включается сама, если в деле есть `letter` или `cards`: сверху письмо, ниже карточки (новые первыми). На экране «точка пройдена» — карточки этой точки. В навигации — счётчик.

**Письмо** — `{"title": "Письмо", "note": "…", "start": "s1", "end": "s10", "states": [...]}`. Состояние:

| Поле | Что |
|---|---|
| `id` | имя состояния |
| `text` | строки письма; `▓` — пятно на месте слова (ширина постоянная — по пятну не понять длину слова) |
| `reveal` | слово под пятном проступило |
| `ruled` | на просвет: двойная линия по линейке под буквами |
| `tip` | кончик полоски: `stuck` — присох; `circles` — две линии до края и кружки, обведённые дважды |
| `stamp` | штамп поперёк («Не сдержано», «Доставлено») |
| `back` | оборот (виден, когда задан) |
| `caption`, `img`, `alt` | подпись; картинка над полоской, если появится нарисованная |

Состояние меняют `letter` у шага (с началом шага), у точки (когда пройдена), `start` и `end` у письма. Письмо открывается крупно с доски в любой момент.

## 6. Ветки А/Б

Любой элемент любого списка (точка, шаг, реплика, вариант, карточка, вопрос на ходу) может иметь `"if"`: `"st4=B"`, `"st4!=B"`, `"st4=A|A2"` или `{"st4": ["A", "A2"]}`. Элемент остаётся, если условие выполнено. Флаги — `flags` в деле; **по умолчанию `A`**. Обе ветки лежат в деле рядом; после выезда владелец меняет одну букву в `flags` — текст не переписывается.
Посмотреть ветку, не меняя дело: `…/play/zilart/?flags=st4:B,st10:B` (на телефоне, после кода). В проверке: `node scripts/player_check.js --flags=st4:B`.
**Плашка полевого теста 🔶 (H-83).** В `?field=1` у реплики или поля, которые звучат запасным текстом из-за флага-факта, плеер ставит служебную плашку «🔶 запасной текст: <флаг> — <что подтвердить>»; если основной текст просто снят (замены нет) — «🔶 скрыто до подтверждения» у соседнего элемента. Флаг-факт 🔶 — тот, что есть в необязательном `"flag_notes": {"f_kand": "сколько эскизов к «Композиции VII»"}`, или в строке `check` с ним сказано «Историк»/«🔶», или он `f_*` при «🔶» в `_flags`. Пояснение: `flag_notes` → фраза из `check` с этим флагом → начало основного (A) текста. Игроку без `?field=1` плашка не видна (`player_check`).
Смена флага посреди прохождения меняет число шагов точки: прогресс текущей точки может съехать — флаги меняют до старта.
**Временные объекты (H-111).** Выставка под открытым небом, сезонный павильон, ремонт — у элемента, который на них опирается (реплика, шаг, вариант, карточка, точка), поле `"temporary": {"what": "«Самосвал» Вима Дельвуа", "until": "2027-01-17", "source": "сайт музея, страница выставки"}`: `until` — **последний день**, когда объект на месте (ГГГГ-ММ-ДД, по Москве), `source` — откуда срок, необязательный `match` — строка для поиска на витрине (по умолчанию слово в «» из `what`). Замена на после срока — ветка Б того же элемента (флаг-факт, как выше). **Плеер после `until` переключает сам (H-117):** элемент с `temporary` снимается, как элемент с непрошедшим `if`, а `"flag": "st4s=B"` в записи ставит флаг-факт на ветку Б (явный `?flags=` важнее; дата — по Москве, один раз при загрузке дела; проверить — `…/play/zilart/?today=2027-01-18`). Записи `temporary.json` попадают в зашифрованное дело через `codes.py seal` (поле `temporary` дела; сам `quest.json` не меняется), и без `flag` плеер их не применит — в `player_check` после срока такая запись красная, с `flag` — предупреждение «плеер снимает». Флаг, которого нет в `flags` дела, — ошибка. За 30 дней до `until` владельцу один раз приходит сообщение в Telegram (H-118: `scripts/temporary_notify.py` в workflow «Telegram — входящие», отметки — `.telegram/temporary-sent.json`; новый `until` — новое сообщение; `--dry --today=2026-12-18` — печать вместо отправки). `scripts/temporary_check.js` (входит в `site_check` и `player_check`): **за 30 дней до `until` — предупреждение**, после — **ошибка** со списком мест в деле и страниц витрины, где объект упомянут (снять, заменить или продлить срок по источнику). Пока `quest.json` заморожен полевым тестом, те же записи — в `quests/<id>/temporary.json` (`{"items": [{…, "flag": "st4s=B", "where": "т.4 scene, реплика Тюфеля"}]}`); после разбора теста — перенести в элемент и удалить файл. Проверить на дату: `node scripts/temporary_check.js --today=2027-01-18`; самопроверка (прошедшая дата на фикстуре краснеет) — `--selftest`.

## 6а. Ветки «по часам работы» (H-45)

Для перехода, который зависит от того, открыто ли здание (ЗИЛАРТ, точка 9а: ТЦ «ЗУМ» насквозь или в обход мимо пресса).

- В деле: `"clock": {"zum": {"label": "ТЦ «ЗУМ»", "open": "10:00", "close": "22:00"}}`. Время — московское, на телефоне игрока. Закрытие после полуночи (`"open": "20:00", "close": "02:00"`) работает. Необязательно: `open_text`, `closed_text` (`{label}`, `{open}`, `{close}`), `closed_button` (по умолчанию «Двери закрыты»), `open_button` («Двери открыты»), `closed_toast`, `open_toast`.
- Значения флага — `open` и `closed`. Условие пишется как у веток А/Б: `"if": "zum=open"`, `"if": "zum=closed"`.
- **Где можно:** реплики `walk`, `scene`, `outro` этой точки и `walk_m` списком: `"walk_m": [{"if": "zum=open", "m": 455}, {"if": "zum=closed", "m": 510}]`. Абзац дороги без говорящего — объектом `{"text": "…", "if": "zum=closed"}`. **У точки и у шага — нельзя**: число шагов не должно меняться на ходу (плеер пишет предупреждение в консоль).
- Как выбирает плеер: на экране дороги к точке — строка «ТЦ «ЗУМ» сейчас открыт, до 22:00» и кнопка «Двери закрыты» (в закрытое время — «Двери открыты»). Ветка определяется по часам, когда игрок впервые видит дорогу к этой точке (событие показа дороги — `showWalk`, а не отрисовка; T-99), и дальше не меняется сама. Кнопка переключает ветку вручную, выбор запоминается и попадает в отчёт полевого теста.
- Проверить без ожидания вечера: `…/play/zilart/?at=23:10` (подставное время) или `?flags=zum:closed`. Автотест: `node scripts/player_check.js --data=scripts/fixtures/quest-format5.json --allow-missing-media` (точка 2 фикстуры).

**ЗИЛАРТ 5.4** вписан: `clock.zum` (часы с таблички пока не проверены — 10:00–22:00), дорога к точке 10 (бульвар) — абзацы `zum=open` / `zum=closed`, реплика кота «Немца вы уже знаете» — в ветке `zum=closed`, `walk_m` 725 / 780 м (от скамейки на ул. Кандинского через «ЗУМ»).

## 6б. Развилка: ветку выбирает игрок

Для продолжения по желанию (Коломенское: «Продлить к дворцу» / «Закончить у ворот», флаг `ext`). Поле `fork` у точки **перед** развилкой:

```json
"fork": {"flag": "ext", "title": "Куда идём дальше?", "text": "…",
         "options": [{"value": "A", "label": "Закончить у ворот", "note": "…"}, {"value": "B", "label": "Продлить к дворцу", "note": "…"}]}
```

- Кнопки — на последнем экране «точка пройдена» этой точки, над «К точке N»; отмечен текущий выбор (по умолчанию — `flags` дела или `?flags=`). Ушли к следующей точке — выбор не меняется.
- Выбор пишется в сохранение (`fl`) и в отчёт полевого теста («Развилка: ext = B»), важнее `flags` дела и ссылки `?flags=`; «Начать заново» его стирает.
- Ветки пишутся как обычно (`"if": "ext=B"` у точек после развилки); у точек **до** развилки и у самой точки с `fork` условий по этому флагу быть не должно — их прогресс не должен меняться.
- Тексты до развилки (вступление, обложка) показывают ветку по умолчанию; про продолжение там пишем «по желанию», без точного числа остановок.
- Проверка: `player_check` нажимает другой вариант, сверяет ветку дела и возвращает выбор.

## 7. Состояние на телефоне

`localStorage` `dvorami:play:<id>`; к прежним полям добавлены `cards` (`[{id, n}]`), `struck`, `letter`, `arrows` (какие «стрелки» показаны), `wa` (вопросы на ходу текущей дороги), `reply`, `sel` (выбор в `pick`/`strike`). Старые сохранения открываются: недостающее заполняется. `seed` — порядок вариантов выбора для этого игрока. `fl` — выбор на развилках (`{"ext": "B"}`).

**Новая версия дела** (H-74): если в сохранении `version` не та, что в `quest.json`, а игрок уже начал, плеер вместо экрана показывает «Вышла новая версия дела»: «Начать заново» (обложка, прогресс стирается) или «Продолжить» (то же место, точка и шаг ограничиваются новым числом шагов); в полевом режиме — ещё «Отправить отчёт старой версии». Выбор пишется событием `version` в отчёт и больше не спрашивается. Поэтому **любая правка `quest.json`, которую игрок должен увидеть, поднимает `version`**, а правка опечатки без смены смысла — может не поднимать.

**Витрина = сценарий** (T-140): новая `version` краснит `node scripts/site_check.js --sync`, пока витрина дела (страница, карточки, OG, `site/llms*.txt`, посты канала) не сверена со сценарием и версия не вписана в `platform/site/story-sync.json`. Снятого из сценария героя, год или фразу впишите в той же правке в `quests/<id>/retired.json` (`items: [{"text": "…", "why": "когда и почему снято"}]`) — проверка ищет их по всей витрине; герои блока «Кто ведёт дело» на странице дела должны быть среди `speakers`.

## 8. Безопасность

На стенд дело попадает только зашифрованным (`docs/codes.md`). `scripts/codes.py leakcheck` ищет в сайте отрывки текстов дела — в формате 5 и в репликах, карточках, письме, вариантах, вопросах на ходу. Картинки и звук дела (`site/play/<id>/media/`) публичны: в именах файлов и подписях — без ответов (`team/std/spoilers.md`).
