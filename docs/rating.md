# Рейтинг дел: откуда берутся оценки и как принимать их без Telegram

## Как устроено сейчас (25.11)

- **Один источник:** `site/assets/ratings.json` собирает `scripts/build_ratings.py` из `feedback/*.jsonl`. Руками его не правят, тест `test_ratings_json_in_site_is_real` сверяет файл со сборкой.
- **Что считается:** оценки 1–5 из бота после финала дела (`done_<дело>`, `confirmed: true`) и, когда появится, с сайта (`kind: rating, source: site`). Один игрок (псевдоним) — одна оценка дела, засчитывается последняя. Оценки из меню «Оставить отзыв» без финала в рейтинг не идут. **В рейтинг идут только оценки, одобренные владельцем** (раздел «Модерация» ниже).
- **Что в публичном файле:** по каждому делу только `sum`, `count` и разбивка `bot`/`site`. Псевдонимов, текстов и времени отдельных оценок там нет.
- **Порог 5 оценок.** Если оценок меньше, на карточке и странице дела рейтинга нет — только статус («Скоро в продаже»; владелец 26.11 отказался от «Новое дело»), а бот пишет «ваша среди первых». Начиная с 5 оценок показываются звёзды с частичной заливкой и «4,86 · 37 оценок». Тогда же в JSON-LD страницы появляется `aggregateRating`, до порога его нет.
- **Обновление:** бот сохраняет отзывы через `scripts/feedback_bot_commit.sh`, и тот же шаг пересобирает `ratings.json`. HTML карточек при этом не пересобирается: `site.js` подтягивает свежий `ratings.json` при открытии страницы. Без JS остаётся значение на момент сборки.
- **Почему не «предзаполнить».** Владелец предложил стартовые 4,71+ и 23–119 оценок. Показывать покупателю придуманные оценки нельзя: ст. 5 закона «О рекламе» запрещает недостоверную рекламу, а оценка, выданная за мнение реальных игроков, может стать претензией ФАС или жалобой площадки. Если подмену обнаружат, доверие к остальным отзывам тоже пропадёт. Честные альтернативы: до 5 оценок — без рейтинга, только статус дела; оценки тестеров полевого теста, если они реально прошли дело, с пометкой «оценки тестеров»; цитаты из отзывов тестеров с их согласия.

## Модерация (с 26.11)

**Как это выглядит.** Игрок ставит звёзды на финальном экране и нажимает «Оставить отзыв в Telegram» — бот @dvorami_bot уже знает оценку и просит пару слов. Когда игрок закончит (или бросит разговор — тогда через сутки), вам в чат с @dvorami_bot приходит карточка: оценка, дело, что понравилось, где было непонятно, можно ли цитировать. Под ней две кнопки:
- **✅ В рейтинг** — оценка начинает считаться в звёздах на сайте и в боте;
- **🚫 Не учитывать** — оценка остаётся у нас в истории, но в рейтинг не идёт.

Это и есть «галочка в админке». Передумали — под карточкой остаётся кнопка «убрать» или «вернуть». Пропустили карточку — отправьте боту **/moderate**: он покажет все оценки, по которым ещё нет решения (по 10 за раз).

**Важно.**
- Карточки приходят в чат с **игровым** ботом @dvorami_bot, а не с ботом команды: нажатие кнопки получает тот бот, который её прислал. Если вы ни разу не нажимали в @dvorami_bot «Запустить», карточка придёт через бота команды без кнопок, с подсказкой — откройте @dvorami_bot и отправьте /moderate.
- Нажимать кнопки может только владелец (тот же Telegram, что в `TELEGRAM_CHAT_ID`). Чужое нажатие ничего не меняет.
- Пока решения нет, оценка в рейтинге **не** считается. Порог «от 5 оценок» прежний: звёзды на сайте появятся, когда одобренных станет 5.
- Если игрок оценил дело второй раз, считается его последняя одобренная оценка.
- Решения хранятся в `feedback/moderation.json`: только номер отзыва и статус, без имён и текстов. Отзывы без финала (из меню «Оставить отзыв») на модерацию не приходят — они и раньше в рейтинг не шли; низкие из них по-прежнему сразу приходят вам сообщением.
- Обновление: решение сохраняется в репозиторий вместе с отзывами (раз в 30 минут), тогда же пересобирается `ratings.json` — звёзды на сайте меняются в течение ~получаса.

**Что изменится после переезда** (своя облачная функция — A-58/A-20). Оценка будет уходить прямо с финального экрана, без Telegram, и попадать **в ту же очередь**: такая же карточка с кнопками в @dvorami_bot и в /moderate (запись `kind: rating, source: site` — бот и сборка рейтинга её уже понимают). Для вас ничего не поменяется: те же две кнопки.

## Конкуренты (коротко)

Поиск (WebSearch) не дал страниц самой «Клаустрофобии» с карточками, только статьи и отзовики. По памяти: на карточке квеста у них средний балл и число отзывов рядом с названием, а отзывы собираются после игры от тех, кто реально играл (по брони). Это не проверено. Посмотреть стоит вручную: https://claustrophobia.com/ (одна страница каталога и одна страница квеста). Наш вид сделан по тому же образцу: балл с сотыми, число оценок, звёзды, и оценивают только прошедшие дело.

## Как принимать оценку прямо с сайта, без Telegram

Сайт статичный (GitHub Pages) и сам ничего принять не может, нужен приёмник. Варианты:

| Вариант | Плюсы | Минусы | Цена | Что нужно от владельца |
|---|---|---|---|---|
| **A. Функция в Yandex Cloud (Cloud Functions + YDB serverless или Object Storage)**: плеер шлёт `POST {quest, rating, user}`, функция проверяет и пишет | Доступно из России, не зависит от Telegram; ответ мгновенный; можно проверять код доступа (только оплатившие) и ограничивать частоту | Нужен аккаунт и платёжный аккаунт Yandex Cloud (карта или юрлицо), код и секрет для выгрузки | В пределах бесплатного уровня Serverless (порядка 1 млн вызовов функций в месяц, у YDB serverless тоже свой бесплатный объём). Для нас 0 ₽, при превышении — копейки за тысячу вызовов. Лимиты проверить на странице тарифов перед подключением | Зарегистрировать Yandex Cloud, привязать платёжный аккаунт, создать сервисный аккаунт; ключ — в GitHub Secrets |
| **B. Форма-сервис (Яндекс Формы и т. п.)**: кнопка «Оценить» открывает форму | Ничего не программировать; бесплатно; доступно из России | Уход со страницы, игрок теряет нить; нет привязки к финалу (накрутки); ответы надо выгружать вручную или через API; чужой интерфейс | 0 ₽ | Создать форму под своим аккаунтом и дать ссылку |
| **C. GitHub Issues/Discussions через посредника**: сайт → наш приёмник → issue в репозитории → workflow складывает в `feedback/` | Хранение и учёт уже наши (`build_ratings.py`) | Напрямую из браузера нельзя: нужен токен GitHub, а на статичной странице его не спрятать. Значит, всё равно нужен посредник из A. GitHub из России работает нестабильно | 0 ₽ + посредник | То же, что в A |
| **D. Сторонние виджеты отзывов** (агрегаторы, карточка в Яндекс Картах / Tripster) | Доверие площадки, SEO | Оценка уходит на чужую площадку, в наш рейтинг не попадает; модерация не наша | 0 ₽ (часто с платными тарифами) | Аккаунты на площадках |
| **E. Офлайн-очередь в плеере + отправка позже** (дополнение к A) | Оценка не теряется при плохой связи: плеер хранит её и шлёт, когда сеть появится | Только вместе с A | 0 ₽ | — |

**Рекомендация: A + E.** Это функция в Yandex Cloud: плеер (`sendRating(value)` в `site/play/player.js`) шлёт оценку в функцию, функция раз в сутки (или workflow по расписанию) отдаёт агрегат, который ложится в `feedback/` как `kind: rating, source: site`. Дальше всё уже работает: `build_ratings.py` → `ratings.json` → карточки и бот. Если связи нет, плеер держит оценку в очереди. Пока функции нет, `sendRating` открывает бота (`done_<дело>`), как сейчас.

Защита от накрутки: оценку принимать только вместе с кодом доступа к делу, когда начнутся продажи. Код проверяет функция, в публичный файл он не попадает. До продаж: один голос на устройство (случайный id в `localStorage`) и ограничение частоты по IP в функции. IP не хранить.

Без ответа владельца сайт продолжит собирать оценки только через бота. Вопрос в APPROVALS: «Подключить Yandex Cloud (бесплатный уровень, нужен платёжный аккаунт) для приёма оценок с сайта?»
