# Канал @dvorami_quest: как посты попадают в канал

Правила контента — `docs/marketing/channel-rules.md`, голос — `docs/marketing/tone-of-voice.md`, план — `docs/marketing/content-plan.md`.

## Как устроено
```
posts/NNN-слаг.md   шапка (дата, время МСК, статус, картинка) + текст в Telegram-HTML
img/NNN-слаг.png    картинка 1080×1350, рисуется кодом из img/src/NNN-слаг.html
scripts/channel_post.py      публикует одобренные посты
scripts/channel_render.py    рисует картинки (Playwright, внешние запросы заблокированы)
.github/workflows/channel-post.yml   раз в час (в :07) запускает публикацию
```
Жизнь поста: `draft` → владелец одобряет → `approved` → в ближайший час после `date`+`time` скрипт отправляет → `published` + `message_id` + `published_at` (коммит «Канал: опубликован пост»). За один запуск уходит не больше одного поста, поэтому даже пачка одобренных не «завалит» ленту.

## Что нужно сделать владельцу (один раз, ~3 минуты)
1. **Токен бота в GitHub.** Если секрет `PLAYER_BOT_TOKEN` (токен @dvorami_bot) уже добавлен по A-21 — ничего делать не нужно. Иначе: https://github.com/jastiss/dvorami/settings/secrets/actions → New repository secret → Name `PLAYER_BOT_TOKEN`, Secret — токен из @BotFather.
2. **Сделать @dvorami_bot админом канала.** В Telegram: откройте канал @dvorami_quest → название канала вверху → «Изменить» (карандаш) → «Администраторы» → «Добавить администратора» → найдите `dvorami_bot` → оставьте включённым только **«Публикация сообщений»** (остальное можно выключить) → «Готово».
3. **Одобрить посты.** Либо откройте файл поста на GitHub (карандаш «Edit») и замените `status: draft` на `status: approved` → Commit; либо напишите команде в Telegram «посты 001–005 да» (или «001 да, 003 нет: …») — Продюсер поменяет статус сам.

Проверить без публикации: GitHub → Actions → «Канал — публикация постов» → Run workflow → галочка «Только показать».

## Почему токен игрового бота, а не командного
- `PLAYER_BOT_TOKEN` (@dvorami_bot) — публичный бот бренда: его ссылка и так стоит в постах («Предложить район»), подписчики видят его в списке админов канала — это нормально.
- `TELEGRAM_BOT_TOKEN` — служебный бот команды: он читает указания владельца и шлёт отчёты. Давать ему права в публичном канале — смешивать роли: ошибка в коде отчётов не должна уметь писать в канал, и наоборот.
- Публикацию «от имени канала» Telegram делает одинаково для любого бота-админа, разницы для подписчиков нет.

## Как сделать новый пост (для команды)
1. Скопируйте ближайший пост той же рубрики в `posts/NNN-слаг.md`, поправьте шапку (`id`, `date`, `time`, `rubric`, `type: photo|text|poll`, `image`, `sources`), `status: draft`.
2. Картинка: скопируйте шаблон из `img/src/`, поменяйте текст, `python3 scripts/channel_render.py NNN --preview` (превью 360 px — проверка «читается на телефоне»).
3. `python3 scripts/channel_post.py --check` — разметка, длина подписи (≤ 1024), картинка, **спойлеры** (слова-ответы и годы-улики из `quests/*/quest.json`). Красное — не отдаём на одобрение.
4. Опрос: `type: poll`, `question:` и список `options:` (строки с `  - `); текст под шапкой не отправляется.
5. Кнопка под постом: `button_text:` + `button_url:`.

## Если что-то пошло не так
- Telegram ответил ошибкой — пост остаётся `approved`, в логе Actions будет причина (чаще всего: бот не админ канала). Повтор — в следующий час.
- Пост ушёл, а коммит статуса не прошёл (редко) — при следующем запуске пост уйдёт **повторно**. Если в логе Actions есть «опубликован», а статус в файле не сменился, — поставьте `status: published` руками.
- Удалить опубликованный пост скрипт не умеет: это делается в Telegram вручную, затем `status: published` остаётся, а в `state/DECISIONS.md` — запись почему.
