# Коды доступа к делам

Решение по указанию владельца 23.11: экран кода в начале квеста, мастер-код для тестов владельца в секретах GitHub, система выпуска и хранения кодов. Это этап **без сервера** — до оплаты и облачных функций (A-17, `docs/purchase-flow.md`).

## Что нужно от владельца — один раз, 3 минуты

1. Придумайте мастер-код: 12 знаков, например `K7M4-Q2PX-9HTW` (буквы A–Z без O, I, L и цифры 2–9). Можно попросить команду сгенерировать — но тогда код пройдёт через чат; лучше придумать самому или запустить `python3 scripts/codes.py master` у себя. Сохраните его в менеджере паролей или в заметке на телефоне.
2. Откройте https://github.com/jastiss/dvorami/settings/secrets/actions → зелёная кнопка **New repository secret**.
3. **Name:** `QUEST_MASTER_CODE` · **Secret:** ваш мастер-код → **Add secret**.
4. Скажите команде «секрет заведён» (сам код не присылайте). Продюсер перезапустит сборку стенда — через 2–3 минуты код заработает.
5. Проверка: https://jastiss.github.io/dvorami/play/zilart/ → экран «Код доступа» → ваш мастер-код → «Открыть дело». Регистр, пробелы и дефисы не важны; русская раскладка тоже (К, М, Р… превращаются в латинские).

Пока секрета нет, сборка не падает: на стенде экран кода, но ни один код не подходит.
Тестерам свой мастер-код не давайте — для них есть выпущенные коды (ниже): их можно отозвать по одному.

## Как устроено

| Где | Что лежит | Секретно? |
|---|---|---|
| Секрет GitHub `QUEST_MASTER_CODE` | мастер-код владельца | да, видит только сборка |
| `quests/<id>/quest.json` | дело целиком (источник истины) | **нет** — репозиторий публичный, см. «Ограничения» |
| `quests/<id>/codes.json` | соль дела и выпущенные коды: номер, метка, дата, отзыв, идентификатор и «запечатанный» ключ | нет: самих кодов там нет, распечатать запись может только сборка с мастер-кодом |
| `site/play/<id>/quest.locked.json` | зашифрованное дело и таблица «идентификатор кода → обёрнутый ключ» | нет: собирается при каждой сборке, в репозиторий не коммитится |
| Телефон игрока | введённый код (`localStorage`, ключ `dvorami:code:<id>`) | — |

1. **Сборка стенда** (`.github/workflows/pages.yml` → `scripts/codes.py seal`): дело шифруется AES-GCM-256 **новым случайным ключом содержимого** K. Открытый `quest.json` в сайт не попадает; шаг `codes.py leakcheck site` роняет сборку, если в сайте нашёлся текст точек, подсказок, улик или ответы дела.
2. **Код → ключ.** Код (без дефисов, заглавными) → PBKDF2-HMAC-SHA256, 200 000 итераций, соль дела → 32 байта → из них идентификатор (16 байт SHA-256) и ключ-обёртка. В таблице сайта под идентификатором лежит K, зашифрованный ключом-обёрткой. Ни кода, ни его хэша в сайте нет; проверить догадку можно только теми же 200 000 итерациями.
3. **Выпущенные коды.** Из мастер-кода выводится ключ выпуска (X25519). `codes.py issue` знает только его открытую часть: генерирует код, считает идентификатор и ключ-обёртку, запечатывает ключ-обёртку под ключ выпуска и пишет в `codes.json`. Сборка распечатывает записи мастер-кодом и кладёт в таблицу. Отозванный код в таблицу не попадает.
4. **Плеер** (`site/play/player.js`, `unlock()`): Web Crypto повторяет шаг 2 на телефоне (0,1–0,5 с). Верный код — дело открывается и код запоминается на устройстве; неверный — понятная ошибка. Ссылка `…/play/zilart/#code=XXXX-XXXX` подставляет код и сразу убирает его из адреса (не попадёт в Метрику и в скриншоты); `?code=` тоже понимается.
5. **Офлайн**: service worker кэширует `quest.locked.json`, код хранится на телефоне — после первого открытия дело идёт без сети, как раньше.

## Выпуск и отзыв кодов (команда)

Нужен `pip install cryptography`. Коды выводятся только в терминал или в файл **вне репозитория** (внутри — только в `.codes/`, она в `.gitignore`).

```bash
# один раз, после того как владелец завёл секрет: сборка печатает в журнале «ключ выпуска: …»
python3 scripts/codes.py set-issuer --quest zilart <ключ из журнала>

python3 scripts/codes.py issue --quest zilart -n 5 --label "полевой тест 30.11" --out ~/dvorami-codes.txt
python3 scripts/codes.py list --quest zilart          # номера, метки, даты, отозван ли
python3 scripts/codes.py revoke --quest zilart --n 3  # или: revoke --quest zilart K7M4-Q2PX
```

После `issue` и `revoke` — закоммитить `quests/zilart/codes.json`; коды начинают (перестают) работать после сборки стенда. Коды владельцу — только личным сообщением, не в отчёт и не в репозиторий: отчёты публичные.

Формат кода — `XXXX-XXXX`: алфавит `23456789ABCDEFGHJKMNPQRSTUVWXYZ` (31 знак, без 0/O, 1/I/L), ≈ 8,5·10¹¹ вариантов. Мастер-код — 12 знаков.

**Смена мастер-кода** (утёк, или тестер его узнал): завести новый секрет с тем же именем → сборка печатает новый ключ выпуска → `set-issuer` с ним. Старые выпущенные коды перестают работать (сборка предупредит) — их нужно выпустить заново. Поэтому до этапа с сервером мастер-код без нужды не меняем.

**Тесты.** `node scripts/player_check.js` и `node scripts/site_check.js` шифруют дело на лету временными кодами (`codes.py selftest-bundle`) — в репозиторий они не попадают. `player_check` проверяет экран кода, неверный, отозванный и «похожие знаки», верный мастер-код и выпущенный код, вход по ссылке `#code=`, запоминание кода.

## Ограничения — честно

- **Репозиторий публичный.** Пока дело лежит открытым в `quests/zilart/quest.json` на GitHub, код защищает **сайт**, а не дело: кто найдёт репозиторий, прочитает квест целиком. Полная закрытость — после закрытия репозитория или переезда (A-20) либо когда контент отдаёт облачная функция по действующему коду (этап 1, `docs/purchase-flow.md`).
- **Перебор кодов без сервера.** Таблицу и соль видит любой. 200 000 итераций PBKDF2 делают одну догадку дорогой, но не невозможной: видеокарта проверяет порядка десятков тысяч кодов в секунду, так что при сотне действующих кодов упорный человек найдёт один за дни. Для тестов и первых продаж этого хватает; продажи в масштабе — только с сервером (ограничение попыток).
- **Срок действия, число телефонов, общий прогресс** без сервера невозможны: код действует, пока не отозван, на любом числе устройств. Это этап с сервером (`docs/purchase-flow.md`, разделы 3–4): коды — хэшем в YDB, активация, 30 дней после старта, до 6 телефонов, 5 неверных попыток в минуту. Тогда `codes.json` заменит таблица `codes`, а экран кода в плеере останется тем же.
- **Отзыв** срабатывает со следующей сборки; телефон, уже открывший дело, держит его в кэше до обновления страницы с сетью.
- **Слабый мастер-код** (дата рождения, «1234») подбирается быстро и открывает выпуск всех кодов — берите 12 случайных знаков.
