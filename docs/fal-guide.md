# fal: генерация изображений, аудио, видео — правила для команды

fal — платный сервис владельца (pay-as-you-go) с десятками моделей: изображения, озвучка, музыка, звуки, видео, анимация, 3D. Подключён как коннектор `fal` (инструменты `mcp__fal__*`).

## Главное правило: деньги — только с одобрения владельца

- **Ни одной платной генерации без строки «одобрено» в `APPROVALS.md`.** Бесплатно можно: искать модели, смотреть схемы и цены (`recommend_model`, `search_models`, `get_model_schema`, `get_pricing`).
- Вопрос в APPROVALS по форме: что генерируем и зачем · модель · сколько штук · **оценка в $** · ссылка на готовый промпт (`quests/<id>/media/specs/…`). Ответ владельца: «A-N да».
- Одобрение действует ровно на то, что в нём написано (модель, количество, бюджет). Нужно больше вариантов или другая модель — новый вопрос.
- **Не повторять платную генерацию автоматически.** Ошибка или «статус processing» — читать результат по `request_id` (`wait_for_jobs`), а не запускать заново.
- Баланс кончился (`billing_block`) — остановиться, написать в отчёте одной строкой, не проверять в цикле.
- Каждую генерацию записать в `state/MEDIA_SPEND.md`: дата, что, модель, штук, оценка $, `request_id`, куда сохранено.

## Как работать

1. **Промпт готовится заранее и бесплатно** — Медиапродюсер пишет его в `quests/<id>/media/specs/<NN>-<что>.md` по скиллу `image-generation` (для изображений) и правилам ниже. Режиссёр/Арт-директор принимают промпт до траты денег.
2. **Модель выбирает `recommend_model`** — с `operation`, `requirements` (формат, язык, длительность) и `budget` (потолок в $). Не угадывать endpoint по памяти, копировать ID точно.
3. **Сначала черновик дешёвой моделью, финал — дорогой**, и только когда черновик принят.
   **Правка понравившейся fal-картинки — через `/edit` той же картинки, а не перерисовкой вектором с нуля** (владелец 23.11: векторные «доработки» ключа потеряли то, что нравилось). Вектор — только как точная обводка принятого эскиза.
4. Запуск — `run_model` (картинки, озвучка) или `submit_job` + `wait_for_jobs` (видео, музыка, 3D — долго). Входные данные строить по `input_contract` из `recommend_model`.
5. Результат скачать в `quests/<id>/media/assets/` — **сначала напрямую `curl` (с 26.11 *.fal.media из среды доступен), запасной путь — workflow «Медиа — скачать из fal»**: `gh api -X POST repos/jastiss/dvorami/actions/workflows/fetch-media.yml/dispatches -f ref=main -f 'inputs[url]=<ссылка fal>' -f 'inputs[path]=<путь в репозитории>'`, через ~1 мин `git pull` (крупное видео — оставить ссылку fal и сохранить в fal Assets), записать в `MEDIA_SPEND.md` и `media/LICENSES.md` (модель, дата, условия коммерческого использования).

## Анимированные ролики: опыт коллеги (таблица расходов, 24.11)

Владелец прислал таблицу коллеги: 13 роликов-эксплейнеров и две серии с персонажами, всего **$60,7**, из них анимация — **$38,4 (63%)**. Сам файл в репозиторий не кладём, ниже — выжимка. Цены сверены через `get_pricing` 24.11.

**Конвейер одного ролика** (≈ $3,5–6,5, у нас — те же шаги):
1. Ресёрч и сценарий — LLM (у коллеги Sonnet + Tavily), копейки.
2. Ключевые кадры — `fal-ai/nano-banana/edit` ($0,04) для массовых, `fal-ai/nano-banana-pro(/edit)` ($0,15) для главных; 10–40 кадров на ролик.
3. **Vision-проверка каждого кадра** моделью до анимации (~$0,005 за кадр) — брак отсеивается до дорогого шага. У нас — Арт-директор смотрит кадр через Read.
4. Анимация кадра — `fal-ai/kling-video/v2.5-turbo/pro/image-to-video`: **$0,07/с** (5 с = $0,35, 7,5–10 с = $0,5–0,7); 4–22 клипа на ролик. Основная статья расходов.
5. Голос — ElevenLabs turbo v2.5 (~$0,01 за реплику), музыка — ElevenLabs music (~$0,14 за трек).
6. Липсинк говорящего персонажа — `fal-ai/kling-video/lipsync/audio-to-video`: **$0,014 за единицу, ~$0,07 за вызов** — в разы дешевле OmniHuman ($0,14/с, мы платили так за Зилю, A-41).
7. Подписи и сборка — LLM + монтаж кодом.

**Серии с постоянным героем:** один раз — лист персонажа (эмоции, планы, пропсы) на `nano-banana-pro` + `/edit` (~20 вызовов ≈ $3) и голос через Voice Design; дальше каждый кадр — `/edit` от листа, так герой не «плывёт».

**Что не брать:** `bytedance/seedance-2.0/image-to-video` — ~$1,37 за клип, вчетверо дороже Kling; у коллеги только в черновике «реалистичного 3D».

**Для нас (T-66, медиакарта):** видео — только в ключевых местах (вступление и финал дела, оживление Зили). Ориентир на один говорящий клип Зили: 2–3 кадра pro ($0,45) + 2–3 клипа Kling по 5 с ($1,05) + липсинк ($0,2) + голос ≈ **$1,8**; на квест с 4–6 такими клипами — **$7–11**. Говорящего персонажа — Kling + lipsync вместо OmniHuman. Каждая генерация — по одобренному вопросу в APPROVALS.

## Промпты: как писать

**Изображения** (подробно — скилл `image-generation`):
- Порядок: что за кадр и для чего → субъект (кто, поза, эмоция, детали) → стиль (направление, техника, фактура) → композиция и ракурс → палитра (hex-коды из `platform/design/BRAND.md`) → свет → ограничения.
- Писать по-английски, конкретно и зрительно: не «красивый», а «diagonal composition, large red circle behind the bird, halftone paper texture».
- Стиль квеста — из бренд-гайда: ЗИЛАРТ — «Авангард» (чёрный, off-white, сигнальный красный #E1251B, геометрия, диагонали).
- Всегда: `No text, no letters, no logos, no watermark` — текст поверх кладём вёрсткой, не генерацией.
- Не называть живых художников и чужих персонажей; описывать стиль словами (эпоха, техника, приёмы).
- Персонажи (Зиля, Кот Тюфель, свидетели): после первого принятого изображения сохранить его как сущность в fal Assets (`library_create`, `create_entity`, тип `character`) и дальше генерировать с этой референсной картинкой — чтобы персонаж был узнаваем во всех сценах.
- **Коллекция квеста в fal Assets:** каждая генерация, которую храним или показываем владельцу, сразу сохраняется в коллекцию квеста — `library_create` → `{operation: "save_job_outputs", job: {endpoint_id, request_id, response_url}, collection_id}`; отклонённое не сохраняем. Id коллекции — в `quests/<id>/media/README.md` или `media/casting/README.md`. ЗИЛАРТ: «ЗИЛАРТ — кастинг героев (A-65)», `dc3qu2sregj2mdo1pq3g`. Подробно — `team/playbooks/media-producer.md`, «fal Assets».
- Формат под место: карточка квеста 4:5, обложка 16:9, сторис 9:16. Разрешение 1K для черновика, 2K — для финала.

**Озвучка:**
- Текст — ровно из утверждённого сценария, без правок «на лету».
- ElevenLabs v4: эмоции тегами в квадратных скобках (`[playful]`, `[whispering]`, `[excited]`), ударения в сложных словах — IPA между слэшами. `language_code: "ru"`.
- MiniMax 2.8 HD: паузы `<#0.5#>`, междометия `(laughs)`, эмоция в `voice_setting.emotion`.
- Один голос на персонажа на весь квест: записать в `quests/<id>/media/voices.md` (модель, голос, параметры, seed) — только действующий рецепт, ≤ 25 строк; история проб — в `state/MEDIA_SPEND.md`.
- Реплика — до 90 секунд, иначе дробить.

**Музыка и звуки:** описывать жанр, инструменты, темп (BPM), настроение, длительность и «без вокала», если фон.

## Чужие изображения: только законные исходники

- Нейросеть **не делает чужую картинку «своей»**: переработка фото или картины с правами — всё равно производное произведение. Исходник для обработки — только: общественное достояние (автор умер > 70 лет назад; картины XIX века, Кандинский и т. п.), CC0 / CC BY / CC BY-SA с указанием автора, собственные фото владельца.
- Источник — страница файла на Wikimedia Commons с лицензией; не брать снимки с сайтов музеев, фотостоков, новостей, соцсетей.
- В `media/LICENSES.md` — исходник, автор, год, лицензия, что сделано, модель.
- Сначала бесплатное: дуотон, полутон, обрезка, фактура — кодом. fal — для оживления, достраивания формата, реставрации, перерисовки в стиль.
- Пример набора: `quests/zilart/media/specs/01-public-domain-processing.md`.

**Что хранить в репозитории:** принятый файл и то, из чего его собирают (сырой голос утверждённой реплики, звук). Промежуточные копии (ненормализованные, «raw» отклонённых вариантов, дубли) — не коммитить; отклонённое, которое ждёт решения или служит примером, — в `archive/<тот же путь>`. Видео и тяжёлое — только то, что ждёт решения или идёт в продукт.

## Кто что делает

- **Медиапродюсер** — промпты, выбор модели, вопрос в APPROVALS, генерация после одобрения, учёт трат.
- **Арт-директор / Режиссёр** — принимают промпт до генерации и результат после.
- **Продюсер** — следит, чтобы ни одна платная генерация не прошла без одобрения, и показывает траты в отчёте.
