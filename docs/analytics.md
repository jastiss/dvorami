# Аналитика: что считаем и как подключить

**Коротко.** Ставим **Яндекс Метрику**: бесплатная, данные хранятся в России, есть карта кликов, воронки (цели) и запись сессий. Вторая система не нужна на старте: Google Analytics для данных россиян нежелательна (трансграничная передача, локализация по 152-ФЗ — [сверить]), а остальное покрывают наши собственные данные — отзывы и «Что-то не так?» из бота (`docs/feedback-bot.md`) и, после запуска продаж, заказы и активации из своей базы (`docs/purchase-flow.md`). Если позже понадобится независимая проверка — Top.Mail.ru (VK), тоже российский и бесплатный.

Код готов: `site/assets/analytics.js`. Пока в нём не вписан номер счётчика, он **ничего не загружает и cookie не ставит**.

## Что сделать владельцу (5 минут)

1. Откройте **metrika.yandex.ru** под вашим Яндекс ID → «Добавить счётчик».
2. Имя: `Дворами`. Адрес сайта: `dvorami.ru` и дополнительно `jastiss.github.io` (стенд). Часовой пояс — Москва.
3. Галочки: «Карта кликов» — да, «Вебвизор» — **пока нет** (см. раздел про 152-ФЗ). Согласитесь с условиями → «Создать».
4. Код вставлять никуда не нужно. Пришлите в бота команды одной строкой: `сайт: метрика 12345678` (номер счётчика — цифры над кодом).
5. Цели (10 штук, таблица ниже) заводятся в интерфейсе Метрики — 10 минут по инструкции. Код для них уже готов.

Регистрация бесплатна. Это действие владельца (регистрация аккаунта) — поэтому делаете вы.

## Куда вставить одну строку (для того, кто правит `site/*.html`)

В каждую страницу сайта перед `</body>`, после `site.js`:

```html
<script src="assets/analytics.js" defer></script>
```

Путь относительный, как у `site.js` на этой странице (для вложенных страниц — `../assets/analytics.js`). Плеер (`site/play/zilart/index.html`) уже подключён.

## Какие `data-track` повесить на страницах

`analytics.js` сам ловит клики по элементам с `data-track`, раскрытие `<details data-track>`, отправку `<form data-track>`. Параметры — атрибутами `data-track-<имя>`. Ссылки на `t.me` без `data-track` считаются автоматически как `tg_click`.

| Элемент | Атрибуты |
|---|---|
| Главная CTA «Выбрать квест» / «Начать дело» | `data-track="cta_main" data-track-place="hero"` (или `cards`, `footer`) |
| Карточка квеста в каталоге (переход на страницу квеста) | `data-track="quest_card" data-track-quest="zilart"` |
| Кнопка «Купить» на странице квеста (сейчас — Tripster/Telegram) | `data-track="buy_click" data-track-quest="zilart" data-track-channel="tripster"` (`site`, `telegram`) |
| «Начать / Пройти квест» (ссылка в плеер) | `data-track="play_open" data-track-quest="zilart"` |
| Подписка на канал Telegram | `data-track="tg_channel" data-track-place="footer"` |
| «Оставить отзыв» | `data-track="review_click" data-track-place="site"` |
| «Предложить район» / «Хочу это дело» | `data-track="suggest_click"` / `data-track="want_click" data-track-quest="<id>"` |
| Вопрос FAQ | `<details data-track="faq_open">` (текст вопроса подставится сам) |
| Карта маршрута (открыть в Яндекс Картах) | `data-track="map_open" data-track-quest="zilart"` |
| Любая форма (подарок, подписка — когда появятся) | `<form data-track="form_submit" data-track-form="gift">` |

Проверка без счётчика: откройте страницу с `?debug=analytics` — события пишутся в консоль браузера.

## События плеера (уже в коде)

`quest_start`, `point_arrive` и `point_done` (`point`), `hint_open` (`point, step, level`), `answer_reveal`, `step_skip`, `quest_pause`, `quest_resume`, `quest_finish` (`minutes`), `map_open`, `review_click`, `issue_send` (`point, category`). У всех — `quest`, `field` (1 — полевой тест; его исключаем из отчётов).

## Цели в Метрике и воронка

Метрика → Настройка → Цели → «Добавить цель» → тип **«JavaScript-событие»**, идентификатор — имя события из таблицы. Заводим 10 целей (больше не нужно):

| № | Цель (идентификатор) | Что значит |
|---|---|---|
| 1 | `quest_card` | интерес к квесту |
| 2 | `buy_click` | намерение купить |
| 3 | `payment_success` | оплата прошла (появится со страницей «Спасибо», `docs/purchase-flow.md`) |
| 4 | `quest_start` | начали играть |
| 5 | `point_done` | прошли точку (по параметру `point` видно, где бросают) |
| 6 | `quest_finish` | дошли до финала |
| 7 | `review_click` | пошли оставлять отзыв |
| 8 | `issue_send` | сообщили о проблеме |
| 9 | `hint_open` | взяли подсказку |
| 10 | `tg_click` | любой переход в Telegram |

**Составная цель «Воронка покупки»** (тип «Составная цель»): `quest_card` → `buy_click` → `payment_success` → `quest_start` → `quest_finish` → `review_click`.

## Дашборд «что смотреть раз в неделю» (5 минут)

Метрика → «Сводка» → добавить виджеты; или Продюсер сводит в понедельничный отчёт.

1. **Посетители за неделю** и **источники** (поиск, Telegram, Tripster, прямые) — откуда приходят.
2. **Конверсия в покупку**: `buy_click` / визиты страницы квеста и `payment_success` / `buy_click` — где теряем покупателя.
3. **Доходимость**: `quest_finish` / `quest_start` — цель ≥ 80%. Ниже — смотреть, на какой точке обрыв (`point_done` по параметру `point`).
4. **Трудные точки**: `hint_open` и `answer_reveal` по `point`. Точка, где ответ показывают больше чем каждой третьей команде, — загадку переделываем.
5. **Отзывы**: `review_click` / `quest_finish` и средняя оценка из бота (`scripts/feedback_digest.py`). Цель — оценка 5★ и NPS.
6. **«Что-то не так?»**: `issue_send` по точкам + тексты из бота.
7. **Мобильные**: доля телефонов и отказы на телефоне — сайт должен работать в первую очередь там.

## Cookie и 152-ФЗ

- Метрика ставит cookie с идентификатором посетителя; Роскомнадзор и юристы относят такие данные к персональным, на их сбор нужно согласие посетителя ([ppt.ru: «Куки и персональные данные: что требует 152-ФЗ»](https://ppt.ru/columns/jurist-v-it/kuki-i-personalnye-dannye-chto-trebuet-152-fz), найдено 22.11.2026). С 1 сентября 2025 года согласие на обработку персональных данных оформляется отдельно от других документов ([ppt.ru, новость](https://ppt.ru/news/personal-data/oformlyat-soglasie-na-obrabotku-personalnykh-dannykh-nuzhno-budet-po-novomu); [Гарант](https://www.garant.ru/news/1850806/)).
- Поэтому в `analytics.js` по умолчанию режим **`CONSENT = 'opt-in'`**: внизу экрана плашка «Мы используем cookie и Яндекс Метрику… [Отказаться] [Согласен]», и счётчик загружается **только после «Согласен»**. Ответ запоминается на устройстве. Минус — часть посетителей не попадёт в статистику (обычно соглашается большинство, но точной доли мы не знаем).
- Режим `'notice'` (грузим сразу, плашка только сообщает) даёт полные данные, но юридически слабее. Переключать — только после ответа юриста.
- **Вебвизор** выключен (`WEBVISOR = false`): он записывает всё, что человек вводит, включая ответы и тексты «Что-то не так?». Включаем, только если это прямо описано в политике обработки персональных данных.
- Нужна страница политики обработки персональных данных (`POLICY_URL` в `analytics.js`, сейчас заглушка `/privacy/`) и уведомление Роскомнадзора об обработке — общий список см. `docs/payments.md`, раздел «Персональные данные». На тестовом стенде без номера счётчика ничего этого не нужно: данные не собираются.

*Не юридическая консультация: формулировку плашки и политики проверить у юриста.*
