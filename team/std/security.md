# Безопасность

Указание владельца 24.11: «По безопасности проверяй тоже всегда, чтобы не взломали». Репозиторий **публичный**: всё, что в нём есть (включая историю коммитов и журналы Actions), видит любой.

## Проверка 24.11 (Продюсер)
- Токенов, ключей и паролей в файлах и в истории git нет: Telegram-токены, chat_id, `QUEST_MASTER_CODE`, ключи запуска команды — в секретах GitHub (`secrets.*`), в коде читаются из окружения.
- Коды доступа тестеров — в `.codes/` (в `.gitignore`); в `codes.json` и журнале сборки — только открытый ключ выпуска и запечатанные записи.
- Workflows не запускаются от чужих PR (`pull_request_target`, `issue_comment` не используются); у всех, кроме `tg-avatars.yml`, явные `permissions`.
- Открытый риск: сценарии и ответы квестов (`quests/*/quest.json`, `story/`) лежат в публичном репозитории открытым текстом — любой может прочитать разгадку, не покупая. Решение — вопрос владельцу A-48.

## Правила для всех ролей
1. Секреты — только в GitHub Secrets. Никогда не печатать их в журнал, ответ агента, отчёт, DIRECTIVES, Telegram; не писать в файлы репозитория, даже временно.
2. Перед коммитом новых скриптов и workflows — проверка: нет токенов/ключей в тексте, нет `echo` секретов, у workflow есть `permissions` с минимумом прав, внешние входы (сообщения Telegram, имена файлов) очищаются.
3. Боты принимают команды только из своего `TELEGRAM_CHAT_ID`; новые боты — так же.
4. Персональные данные игроков и тестеров (имена, телефоны, фото людей) в публичный репозиторий не кладём.
5. Внешние сервисы: не подделывать User-Agent и не обходить отказы (robot policy, 403, 429) — это и нарушение правил сайта, и риск блокировки. Отказ — вопрос в APPROVALS.
6. В еженедельном итоге (понедельник) — строка «безопасность»: что проверили, что нашли.
