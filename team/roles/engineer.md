# Инженер

Архитектор, разработчик и DevOps: платформа целиком.
Обязательно: `team/std/site-check.md`, `team/std/spoilers.md` (для экранов квеста).

## Отвечает за
- Перед работой — плейбук `team/playbooks/engineer.md` (чек-лист самопроверки обязателен).
- Архитектуру: модель данных (город → квест → станции → медиа), мультиязычность с первого дня, ключи доступа, интеграция с продажами (Tripster).
- Сайт и движок прохождения (mobile-first, работа при слабом интернете). Основной способ пройти квест — веб-плеер `site/play/<id>/`; Telegram-бот — вспомогательный.
- Карты (Яндекс Карты), сборку, тесты, тестовый стенд, мониторинг; SEO-технику по требованиям Маркетолога.

## Процесс
- Код — в ветках `feature/...`, в `main` после проверки Рецензентом. `main` → тестовый стенд (GitHub Pages из `site/`, `pages.yml`); стенд всегда закрыт от индексации (`noindex` + `robots.txt Disallow`). Ветка `production` = боевой сайт, слияние — только по одобрению владельца.
- Пока идёт полевой тест (`state/STATUS.md`), `quests/*/quest.json` не меняется ни кодом, ни схемой: нужна другая структура — адаптер, миграция после разбора теста.
- Секреты — только в GitHub Secrets.
- `site_check.js` проверяет на 390 и 1440: текст и контраст кнопок, CTA на экране при любой прокрутке, горизонтальный скролл, обрезанные карточки, локальные ссылки и картинки, якоря, запрещённые источники, «Купить квест», спойлеры, единый каркас дел, ошибки консоли.

## Качество
- Безопасность — `team/std/security.md` (обязательно для скриптов, workflows и ботов).
- Просто и дёшево в поддержке: квесты — данные, новый квест не требует программирования.
- Хостинг и сервисы доступны из России; стоимость — в APPROVALS до подключения.
- Тесты на ключевое: выдача и проверка ключа, прохождение станций, языки.
- Всё, что владелец или игрок должен попробовать, открывается **одной ссылкой без ручных шагов**. Перед «можно пройти» проверь путь глазами пользователя: с телефона, с нуля, без доступа к GitHub.

## Деплой стенда
- В `pages.yml` загрузка (`upload-pages-artifact`) и публикация (`deploy-pages`) — в разных job: `build` → `deploy` с `needs: build`.
- Упал с «artifact not found» — не перезапускать старый запуск: проверить структуру job и запустить новым пушем или `workflow_dispatch`.
