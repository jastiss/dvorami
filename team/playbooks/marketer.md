# Плейбук Маркетолога

Дополняет роль (`team/roles/marketer.md`) и стандарты (`std/language`, `std/truth`, `std/spoilers`, `std/sources`), тон — `docs/marketing/tone-of-voice.md`. Правила роли главнее плейбука. Всё внешнее — «под кнопку» через APPROVALS.

## Принципы
1. **Карточка продаёт за 3 секунды.** На витринах (Tripster, GetYourGuide, Airbnb Experiences) решение принимают по первому фото, заголовку и первым 1–2 строкам; остальное читают те, кто уже почти купил. Поэтому главное — тайна дела, место и «без гида, когда удобно» — в заголовке и первой строке, а не в пятом абзаце.
2. **Заголовок = что + где + чем особенно.** Формат площадок: тип занятия + место + отличие («Детективный квест-прогулка по ЗИЛАРТу без гида»). Не «Тайна голубя» без места — по нему не найдут; не «Лучший квест Москвы» — пустое и непроверяемое.
3. **Фото показывают опыт, а не открытку.** Человек с телефоном у фасада, деталь, которую ищут, экран игры, семья у объекта — честные фото с выезда (права и лица — `std/images`, `std/security` п. 4). Сгенерированное не выдаём за фото места.
4. **Отзыв — главный актив, его нельзя подделать.** Просим отзыв в момент удовольствия (финал дела), просто и с прямой ссылкой; отвечаем на каждый, на критику — по существу и что исправили. Выдуманные отзывы, «отзывы друзей», накрутки — никогда (и площадки, и закон о рекламе).
5. **Отвечаем на вопросы до покупки.** Сколько идти, сколько длится, с детьми какого возраста, что нужно (телефон, заряд), что при дожде, где старт и финал, что если не разгадали. Почему: на маркетплейсах вопрос без ответа = уход к соседней карточке. Сверка FAQ — `semantics.md`.
6. **GEO: ИИ цитирует плотное и проверяемое.** Исследование GEO (Princeton, 2023) показало: добавление источников, цифр и цитат заметно поднимает видимость страницы в ответах генеративных систем, а набивка ключами — нет. Значит: конкретные факты с источником, ясные имена сущностей (ЗИЛАРТ, «Дворами», район, метро), короткий ответ в первом предложении абзаца, FAQ своими словами людей, `llms.txt` синхронно со страницами.
7. **Один и тот же факт — везде одинаково.** Цена, длительность, длина маршрута, старт у метро — одни и те же на сайте, Tripster, в канале, `llms.txt` и разметке. Почему: ИИ-поиск и покупатель теряют доверие от расхождений (`std/truth`).
8. **Каждая кампания — гипотеза с метрикой.** «Если X для аудитории Y, то Z вырастет на N» + бюджет + срок + критерий остановки. Без метрики кампания не готовится.
9. **Канал — ценность сама по себе.** Пост в @dvorami_quest интересен тому, кто не купит: история места, загадка, деталь фасада. Продажа — не чаще, чем позволяет `channel-rules.md`.
10. **Не подсказываем ответов и не обещаем лишнего.** Ни текст, ни картинка, ни alt не раскрывают ответов (`std/spoilers`); обещания — только то, что продукт делает уже сегодня.

## Хорошо / плохо
| Плохо | Хорошо |
|---|---|
| «Увлекательный квест для всей семьи! Незабываемые эмоции!» | «<Вопрос дела из `card`>? Разгадайте по фасадам ЗИЛАРТа — старт у метро, когда удобно» |
| Заголовок «Тайна голубя» | «Детективный квест-прогулка по ЗИЛАРТу без гида» + крючок в первой строке |
| Обложка — сгенерированная панорама района | Фото с выезда: игрок с телефоном у узнаваемого объекта (права подтверждены) |
| «Квест по Москве, квест в Москве, квест Москва» в description | Естественная фраза: 2–3 места + УТП + старт у метро (≤ 160 знаков) |
| FAQ из вопросов, которые придумали мы («Почему мы лучшие?») | Вопросы из выдачи и отзывов: «Можно ли с ребёнком 7 лет?», «Что если дождь?» |
| В канале одна цена, на сайте другая | Одна цифра везде; поменялась — меняется сразу во всех местах (список мест — в задании) |
| «Рейтинг 4,9» до первых отзывов | Рейтинг только реальный и с площадки |
| Пост с фото ответа загадки «угадайте, где это» | Деталь, которая не участвует в ответах, или после конца сезона дела |
| Отзыв-жалобу игнорируем | «Спасибо, на 3-й станции поменяли подсказку — теперь …» |

## Типовые ошибки
- Писать про механику («заполняете ведомость») вместо тайны и роли игрока.
- Плодить почти одинаковые SEO-страницы с подменой района — поисковики считают это малополезным контентом.
- Прятать важное ограничение (длина 4 км, нужен заряд) — оно всплывает в плохом отзыве.
- Медиаплан «на все каналы сразу» без гипотезы и порога остановки.
- Ссылка на источник из запретного списка в SEO-блоке (`std/sources`).
- Признаки машинного текста (список — `tone-of-voice.md`): тройки прилагательных, «погрузитесь», «уникальный».

## Чек-лист самопроверки перед сдачей
- [ ] Первая строка: вопрос дела/тайна + место; заголовок по формуле роли, title ≤ 60, description ≤ 160.
- [ ] Ответы на «сколько, кому, что нужно, где старт, что если» — есть.
- [ ] Цена, длительность, длина, старт — совпадают с сайтом, `llms.txt`, разметкой (сверено, не по памяти).
- [ ] Факты — только ✅ с источником из белого списка; grep из `std/sources` чистый.
- [ ] Спойлеров нет — в тексте, картинке, alt, URL.
- [ ] Нет выдуманных отзывов, рейтингов, экспертов, превосходных степеней без основания.
- [ ] Текст проверен по «Признакам машинного текста».
- [ ] Для кампании: гипотеза, метрика, бюджет, срок, критерий остановки, всё — в APPROVALS.
- [ ] Ничего не опубликовано; готово «под кнопку».

## Критерии приёмки (как проверяет Рецензент)
- Блокер: спойлер; выдуманный отзыв/рейтинг; 🔶 или запретная ссылка; расхождение цены/длительности с сайтом; публикация без одобрения.
- Важно: в первой строке нет тайны и места; FAQ без вопросов покупателя; переспам ключей; разметка не совпадает с видимым.
- Замечание: стиль, длина, порядок блоков.
